# Domain docs

## Before exploring

Read the root `GLOSSARY.md`, if present, and decisions in `docs/adr/`
relevant to the area being explored.

If these files are absent, proceed silently. The domain-modeling skill
creates them when domain terms or decisions are resolved.

## Layout

This repository uses a single context:

- `GLOSSARY.md`: project vocabulary.
- `docs/adr/`: architectural decision records.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed concept is missing, reconsider the term or note the gap for
domain-modeling.

If a proposal contradicts an ADR, identify the ADR and explain why the
decision should be reconsidered.
